# Describe tool

[← Documentation index](../README.md#documentation)

`describeDirectory` scans an existing DICOM tree and emits a concrete [`DatasetSpec`](./schema-reference.md) reproducing its shape — studies/series grouped by their UIDs, per-file size as `targetSizeKb`, and modality. This closes the loop: real tree → spec → regenerate.

```ts
import { describeDirectory, writeCollectionFromSpec } from 'dicom-synth'

const { spec, stats } = describeDirectory('./real-dataset')
// stats: { dicomFiles, skipped, unknownModality, nonDicomFiles }
await writeCollectionFromSpec(spec, './reproduced')
```

- **Links preserved, shape only otherwise, by default** — no descriptive tags are copied, so nothing but the dataset's structure and its UID link-graph is reproduced. UIDs are preserved as hash-derived synthetics (see [`preserveUids`](#preserveuids) below), never the originals — so the regenerated dataset carries the same cross-file relationships without leaking PHI from the source.
- **Opt-in tag preservation** — `keepTags` copies the named tags verbatim (some datasets are valuable for testing *precisely because* of their problematic tags):

  ```ts
  describeDirectory('./real-dataset', { keepTags: ['Manufacturer', '00080060'] })
  ```

  ⚠️ Tags are copied exactly as found. If a kept tag contains PHI, handling that PHI is the **caller's responsibility** — the tool extracts only what you name.
- **Reserved tags are not kept verbatim**, even when named — they would desync or leak:
  - **Modality** — a preset value (`CT`/`PT`/`MR`/`CR`) is reproduced from the captured `modality` field, so it is not copied. A **non-preset** modality (`US`, `NM`, …) has no field route and *is* kept verbatim, so such datasets round-trip.
  - **Modality type-1 attrs** (`Units`, `DecayCorrection`, `CorrectedImage`, `ScanningSequence`, `SequenceVariant`) — owned by the preset; dropped with a warning.
  - **UID-valued** (any `UI`-VR tag, e.g. `SOPInstanceUID`, `FrameOfReferenceUID`) — never copied verbatim through `keepTags`; use `preserveUids` (below) to reproduce UIDs and their cross-file links PHI-safely. Likewise, a kept **sequence** that carries UID references is kept as its hashed UID skeleton rather than verbatim while `preserveUids` is on (warned) — set `preserveUids: false` to keep such a sequence exactly as found.
- Files in a series collapse into one counted entry only when modality, size, and kept tags all match, so tag/size variation is preserved rather than flattened.
- When a kept tag **varies** across a series, that series is emitted in the [per-instance (`instances`) form](./schema-reference.md#per-instance-form-instances) instead: constant tags are stored once on `series.tags`, varying tags become parallel arrays indexed by instance. This keeps each file's tag tuple correlated and stops the spec growing one entry per file. A series with only constant tags stays in the compact `entries` form.
- **`sizeTolerance`** (fraction, default `0` = exact) folds files whose sizes fall within the same relative bucket into one entry — useful when real slices jitter by a few percent and would otherwise each become a separate entry. The regenerated bytes shift to the bucket's representative value (looser fit, smaller spec). Large files keep their exact `targetBytes`.

  ```ts
  describeDirectory('./real-dataset', { sizeTolerance: 0.05 }) // ±5%
  ```
- <a id="preserveuids"></a>**`preserveUids`** (default `true`) reproduces UIDs and their cross-file links without leaking any real identifier. Every UID-valued attribute is replaced by `hashUid(uidSalt, original)`, using one map across the whole tree — so the same source UID always maps to the same synthetic UID, and links like a shared `FrameOfReferenceUID` survive regeneration. **No original UID is ever emitted.** Well-known standard UIDs (the `1.2.840.10008.` org root — SOP classes, transfer syntaxes) are left untouched, and `SOPClassUID` comes from the modality preset. Set `preserveUids: false` for shape only with freshly minted UIDs (no link preservation).

  ```ts
  const { spec } = describeDirectory('./real-dataset') // preserveUids on by default
  // spec.uidSalt records the salt used; pass uidSalt to pin a specific namespace.
  ```

  - **`uidSalt`** namespaces the hash. When omitted it is **derived from the dataset's own study UIDs**, so a given tree always produces the same synthetic UIDs (reproducible), while different datasets get **disjoint** UID namespaces automatically — no coordination needed. Pass an explicit salt only to force a specific namespace. The salt used is always recorded on the emitted spec.
  - the sweep covers scalar, multi-valued, and **sequence-nested** UID attributes. A sequence containing UID references (e.g. `SourceImageSequence` → `ReferencedSOPInstanceUID`, or the two-level `ReferencedSeriesSequence` → `ReferencedSOPSequence`) is **pruned to a UID-only reference skeleton**: its UID-valued fields are kept (hashed, or verbatim for well-known class UIDs) and every other field is dropped, so image-to-image references survive regeneration without copying any other sequence content. Sequences and items with no hashable UID are dropped entirely.
- <a id="capturetree"></a>**`captureTree`** (default `false`) captures the **real directory structure** as a generic [`tree`](./schema-reference.md#generic-tree-tree) spec instead of the compact studies/series form. Everything identifying is anonymised by construction: directories are unnamed (regenerated as positional `dir-NNN`), DICOM files take synthetic names, and non-DICOM files become `file-NNN` keeping only a short alphanumeric extension (`.csv`, `.log`) — no original name ever leaves the dataset. Grouping still survives without the tree having to align with it: every DICOM node carries its hashed `StudyInstanceUID`/`SeriesInstanceUID` as tags. Requires `preserveUids` (the default); `sizeTolerance` is ignored (one node per file — nothing to fold).

  ```ts
  const { spec, stats } = describeDirectory('./real-dataset', { captureTree: true })
  // spec.tree mirrors the on-disk nesting; stats.nonDicomFiles counts placeholders
  ```

  - **Non-DICOM files are captured, not skipped**: each becomes a sized `non-dicom` placeholder (`targetBytes` = exact size; content is never read or reproduced), counted in `stats.nonDicomFiles`. A non-DICOM file over 512 MB cannot be reproduced as a placeholder and is skipped.
- Without `captureTree`: non-DICOM, unparseable, or ungroupable files (missing study/series UIDs) are skipped and counted. An unsupported `Modality` is emitted as the default (CT) and counted.
- Files larger than 512 MB are captured as [`large-image`](./schema-reference.md#large-image-entry--a-large-file-inside-a-dataset) entries (sized by `targetBytes`). They are read **header-only** — the pixel data is never loaded — so a multi-GB file is described without OOM. A file is skipped and counted if its header cannot be read this way: implicit-VR encoding, or metadata before the PixelData element exceeding ~2 MB. A single file beyond the 50 GB ceiling is also skipped (it cannot be reproduced).
